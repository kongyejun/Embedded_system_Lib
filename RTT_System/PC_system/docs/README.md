# RTT 调试系统使用文档

## 概述

RTTReader 是一个基于 SEGGER RTT (Real-Time Transfer) 技术的嵌入式调试工具，通过 J-Link 调试器实现目标芯片与 PC 之间的高速数据传输。支持自动重连、二进制帧解析、日志记录等功能。

## 主要特性

- **自动连接与重连**：支持精确地址和自动搜索两种连接方式，断线后自动重连
- **二进制帧协议**：高效的数据传输协议，支持格式化数据解析
- **多线程架构**：非阻塞式设计，后台线程处理连接和数据读取
- **日志记录**：自动保存原始数据到带时间戳的日志文件
- **数据回调**：支持实时数据回调函数，便于集成到其他系统
- **帧校验机制**：XOR 校验确保数据完整性，统计丢帧率

## 系统要求

### 硬件要求
- J-Link 调试器（任意型号）
- 支持 RTT 的目标芯片（如 STM32、Nordic nRF 系列等）

## 快速开始

### 基础使用示例

```python
import time
from rtt_connet import RTTReader

# 创建 RTT 读取器实例
reader = RTTReader(
    chip_name="STM32F407VE",    # 目标芯片型号
    log_file=True,              # 启用日志记录
)

# 启动读取器
reader.start()

# 保持运行
try:
    while reader.is_running:
        time.sleep(1)
except KeyboardInterrupt:
    reader.stop()
    print("已停止")
```

### 带回调函数的使用

```python
def on_data_received(text):
    """数据回调函数"""
    print(f"收到数据: {text}", end='')

reader = RTTReader(
    chip_name="STM32H750VB",
    on_data=on_data_received,   # 注册回调函数
    log_file="debug_log.txt",   # 自定义日志文件名
)

reader.start()
```

## 数据帧协议

### 帧格式

```
+------+--------+----------+----------+
| 帧头 | 长度   | 有效载荷  | 校验和   |
| 0xAA | 1 字节 | N 字节   | 1 字节   |
+------+--------+----------+----------+
```

- **帧头 (0xAA)**：固定起始标志
- **长度字节**：整帧总长度（包含帧头、长度、载荷、校验）
- **有效载荷**：实际数据内容，支持格式化字符串编码
- **校验和**：有效载荷的 XOR 校验值

### 载荷编码格式

支持类似 printf 的格式化字符串，但采用二进制编码：

| 格式符 | 数据类型 | 字节数 | 示例 |
|--------|----------|--------|------|
| %d, %i | 有符号整数 | 4 | `%d` → 4 字节大端整数 |
| %u     | 无符号整数 | 4 | `%u` → 4 字节大端整数 |
| %x, %X | 十六进制整数 | 4 | `%08X` → 4 字节大端整数 |
| %p     | 指针 | 4 | `%p` → 格式化为 0x00000000 |
| %f     | 浮点数 | 8 | `%.2f` → 8 字节大端双精度 |
| %%     | 转义百分号 | 0 | 输出单个 % |

**示例载荷**：
```
文本: "Temp: %d°C\n"
二进制: "Temp: " + 0x25 + 'd' + [4字节温度值] + "°C\n" + [校验]
```


## 获取 RTT 控制块地址

1. 编译工程后，在 `.map` 文件中搜索 `_SEGGER_RTT`
2. 找到类似这样的行：
   ```
   0x20001630  _SEGGER_RTT
   ```
3. 将地址更新到代码中的 `konwn_rtt_addr` 参数

## 工作原理

### 连接流程

```
启动
  ↓
打开 J-Link
  ↓
连接目标芯片
  ↓
精确地址搜索 (3秒超时)
  ↓ 失败
自动地址搜索 (40秒超时)
  ↓ 成功
启动读取线程
  ↓
持续读取数据
  ↓ 异常/断线
自动重连
```

### 数据处理流程

```
RTT 读取 → 帧解析 → 载荷解码 → 回调/日志
   ↑                                    ↓
   └────── 异常检测 ←────── 校验失败计数
```

## 常见问题

### 1. 无法找到 RTT 控制块

**症状**：超时提示 "所有 RAM 区域均未找到 RTT 控制块"

**解决方案**：
- 确认目标芯片已上电且程序正常运行
- 检查是否包含 `SEGGER_RTT.c` 到工程
- 在 `.map` 文件中查找 `_SEGGER_RTT` 地址并更新 `konwn_rtt_addr`
- 确认芯片型号名称正确（可通过 J-Link Commander 查询）

### 2. 数据乱码或丢帧

**症状**：`frame_error_count` 计数持续增长

**原因**：
- 目标芯片 RTT 缓冲区溢出
- 读取速度不够快

**解决方案**：
- 增大 `once_read_size` 参数（默认 2048）
- 减小 `read_interval` 参数（默认 0.001 秒）
- 增大嵌入式端 RTT 缓冲区大小（修改 `SEGGER_RTT_Conf.h`）

### 3. 精确地址搜索失败

**症状**：每次都走自动搜索，耗时 40 秒

**原因**：RTT 控制块地址变化（重新编译、修改代码后常见）

**解决方案**：
1. 等待自动搜索成功后，查看终端提示
2. 在 `.map` 文件中搜索 `_SEGGER_RTT`
3. 更新 `konwn_rtt_addr` 参数

### 4. 连接后立即断开

**可能原因**：
- J-Link 驱动版本过低，更新至最新版
- USB 供电不足，使用带电源的 USB Hub
- 目标芯片进入低功耗模式，配置 `SWD_MODE` 或禁用休眠



## 日志文件

### 默认命名规则
```
Primitive_data_20240115_143025.txt
```

### 自定义日志文件
```python
# 使用自定义文件名
reader = RTTReader(log_file="my_debug.log")
# 生成: my_debug_20240115_143025.log

# 禁用日志
reader = RTTReader(log_file=False)
```

### 日志内容示例
```
--- 2024-01-15 14:30:25.123456 开始记录 ---
System Start
Temp: 25°C
Sensor: 0x20001A40
Voltage: 3.3000V
```

## 线程安全说明

- `start()` 和 `stop()` 方法线程安全
- `on_data` 回调在读取线程中执行，应避免耗时操作
- 如回调中需要操作 UI 或网络，建议使用队列转发到主线程
